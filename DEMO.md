# Demo, 10 minutes (Problem 2), Relay first

The agent lives on Relay, built by hand from their nodes. The demo is
the Runs tab: one agent, four branches, fired live with Postman. The
laptop beside it shows the receipts. Judging wants three things: a
live call in an Indian language, the money on screen, tight timing.

Screens: the Relay agent (Runs tab), the receipts page
(`http://localhost:3000/collections`, terminal with `npm run
eval:collections` standing by), Postman with the four event files from
`artifacts/relay-events/` loaded.

Warm-up before the panel:

```bash
cd /home/sajadxdp/klear
npm run db:init && npm run db:seed && npm run db:seed-collections
npm run eval && npm run eval:collections     # receipts, both green
npm run dev
```

## 0:00 The scene (60 seconds)

"Meena runs collections at a regional lender. 4,200 overdue accounts,
six callers. Her list is sorted by loan number, so her callers start
at LN-10001 and spend the day on people who will never pay. The list
cannot tell a forgotten payment from a broken promise from a lie."

"This agent reads the book instead. One trigger, one router, four
branches, and every branch says why it fired. Watch."

## 1:00 The live call (the judged moment)

Postman the Sunita event. The run fires in front of the judges:

- **The Sarvam call script plays, in Hindi**: greeting, loan, amount,
  the recorded-call disclosure, the link. The live call they asked for.
- **The Cashfree payment link appears in the run**: the money they
  asked for. Open it if the panel wants to see the checkout.

"Eighteen days overdue, two promises made and two kept. The calling
band, and she is in it. That call was generated by the agent's own
run, in her language, with the disclosure inside the script."

## 2:30 The other three truths (90 seconds)

Fire the other three events, thirty seconds each:

- **Shanta, hardship on record** → the partial branch: a payment link
  with a 25 percent minimum and a draft that offers a way forward.
  "A borrower who cannot pay gets an offer, not pressure. No pressure
  words exist in any template, because this branch exists."
- **Naseem, claims he paid at the branch, four promises never kept** →
  the verify branch: a note to the manager, no call spent.
  "A claim is either a lifeline or an excuse. This one says four
  promises, zero kept, so the manager asks for the reference before
  anyone picks up a phone."
- **Ravi, ninety days, six promises, zero kept** → the hold branch: no
  call, a note saying why.
  "The queue refuses to waste a call on him, and it says so."

"Four borrowers, four different right answers, one agent, all on
Cashfree's own platform."

## 4:00 The receipts (60 seconds)

Turn to the laptop. Terminal, run the collections eval live:

"The same branch conditions you just watched, measured offline against
outcomes the agent never sees. Our top fifteen finds eleven payers,
loan-number order finds seven, a 1.6 times lift. And the fairness
table: the conditions read days overdue, promise history, hardship and
claims. Name, language, area never enter, and the language distribution
of the top queue tracks the book to prove it. The routers are not a
guess, they are the measured version."

## 5:00 The whole loop, one sentence (30 seconds)

"Trigger, router, branches: verify the claim before the call, offer the
partial when the month is hard, call in her language when she keeps her
promises, and refuse to spend a call on the ones who never pay. Every
decision explainable, every rupee moving on Cashfree."

## 5:30+ Q&A (standby)

"Could it rank on language or community?" The conditions never read
those fields. The fairness table is the proof.

"How do you know the branch logic is good?" Held-back outcomes, 1.6
times lift over list order, printed live.

"What about salary dates?" Same pattern as hardship: a recorded note
field and one more branch, call after payday. The structure extends.

"Does any LLM decide anything?" Sarvam speaks. The decisions are router
conditions a manager can read aloud.

"Fresh file you have not seen?" The conditions read behaviors, not
names or scripts. Postman the new event, the router answers.

"Is this production?" It runs on Cashfree's own agent platform in test
mode, with the same approval rails the platform enforces.
